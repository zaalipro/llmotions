Get ncode

ncode A coding harness where every run, agent and operation is a process, and everything has a progress bar.

Ask for a change and watch it happen. Agents split the work, every tool call runs on its own, and nothing writes to your project beyond the approval mode you picked. One engine, as a native Mac app and as a full-screen terminal session.

One engine, two faces

The Mac app and the CLI run the same engine on the same local database, so a conversation started in one is waiting in the other. They take turns with that database: quit one before you open the other.

Six ways to send a message

The composer carries a mode. It decides what the next message starts: a turn that edits, a read-only plan, a goal, a workflow or a judged plan. Shift+Tab flips between Build and Plan in the app, and a slash command that names a mode selects it.

  • 🛠Buildthe assistant reads, writes and runs
  • ▤Planread-only tools, a step-by-step plan
  • ◎Goalthe next message sets a goal to pursue
  • ⧉Ultrabig tasks become workflows
  • ⧉Workflowthe next message authors and launches a workflow
  • ⚖Consensusa second model judges the plan first

What happens when you send

Every run is a small tree of processes. Stop it and everything under it stops with it.

  1. It thinks

    The agent reads your message, the project's instructions (AGENTS.md and friends, once you trust the project) and the project's memory, and decides what to do.

  2. Each tool call is its own operation

    Reading a file, a search, a command, a web page: every call runs on its own with its own bar, and the agent thinks again when they return. Reads are always allowed; writes and commands follow your approval mode.

  3. A checkpoint before every write

    Right before an agent changes a file, ncode keeps a copy of it. /rewind puts your files back the way they were before an earlier turn.

  4. Big work fans out

    A Lead splits the task across sub-agents that run in parallel, each able to work in its own isolated copy of the project, then checks what came back and reports.

Built for work that takes a while

Type / in the composer. These are the same in both faces.

/swarm <task>
A Lead breaks the task down, hands the parts to sub-agents running in parallel, then verifies and reports.
/goal <text>
Sets a goal every agent keeps in mind, across runs, until it is achieved.
/plan <task>
Plans with read-only tools. Approve the plan and it becomes the prompt for the build.
/consensus
A planner and a judge take turns until the judge approves, against checks you choose: scope, edge cases, keeping changes minimal.
/workflow <name>
Runs a workflow: a deterministic program of phases, agents and panels. Every step it takes on the host is journaled, so a stopped run can resume. /create-workflow writes one with you.
/review
Reviews the uncommitted changes and reports problems.
/compact
Writes a summary the model carries forward: the goal, decisions, files touched, open threads. Nothing in the conversation is deleted.
/rewind
Restores files to how they were before an earlier turn.
Deep research
Runs in the background, from Fastest (one round of four agents) to Ultra (four rounds of ten), and ends in a written report.
Scheduled tasks
A chat, swarm or workflow once, daily, weekly, monthly or on a cron line. They fire from the Mac app.
MCP servers
Add stdio or HTTP servers and switch off the single tools you do not want an agent to see.

Your key, your Mac

Bring your own model

Add a key for Anthropic, or point ncode at any OpenAI-compatible endpoint: OpenAI, OpenRouter, DeepSeek, or a model on your own machine through Ollama or LM Studio. Pick a model for each role: the chat, sub-agents, the judge, research.

  • Anthropic
  • OpenAI
  • OpenRouter
  • DeepSeek
  • Ollama
  • LM Studio
  • any OpenAI-compatible URL

Local first

Conversations, runs, settings and keys live in one database on your Mac. There is no account to create. ncode talks to the providers, search engines and MCP servers you add.

You set how far it goes

A new project starts read-only. Trust it to allow edits. In auto, writes are allowed and safe commands run while other commands ask; a dangerous command asks even in full access. Commands run with a scrubbed environment by default.
